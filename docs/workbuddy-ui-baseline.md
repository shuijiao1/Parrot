| 区域 | 保持 | WorkBuddy 增量 |

积分明细直接展示在账户详情内，包较多时仍在完整详情中分页；旧消息里的“积分明细”按钮兼容回到详情，不再打开二级页。`签到/领额度` 内安排活动执行、自动签到和记录。国际区按能力把活动入口改为试用申请；不为了形式一致显示不适用的签到。

资源包最终到期优先读取已有 `PackageEndTime/EndTime`，缺失时读取 `DeductionEndTime`（毫秒时间戳）；`CycleEndTime` 仅表示本周期结束，不能替代最终到期。未知时间不编造，Token 有效期继续单独展示。

新增账号提供“中国区登录”“国际区登录”“中国区 JSON 导入”。国际区 JSON 导入仍拒绝，不删除已有国际区账号。管理 API 的 WorkBuddy 能力说明与此一致：`browserLoginRealms=[cn,global]`、`importRealms=[cn]`、`clientProfilesByRealm={cn:cli,global:ide}`；原 `clientProfile=cli` 保留为中国区兼容默认值。

国际区入口使用 `www.codebuddy.ai`、`platform=ide` 的网页登录流程：点击入口 → 打开授权链接 → 按“已登录，检查状态”轮询 → 显示国际区身份预览 → 确认保存。等待、身份信息暂不可用、过期、取消与同身份覆盖沿用共享流程，不回退为 JSON 导入；保存时记录国际区 `ide` profile。中国区 `cli` 流程与已有国际区 `cli` 账号的原域名／刷新方式保持。

模型目录只把真实存在的 `auto/default` 显示为 `workbuddy-auto/workbuddy-default` 或 `cursor-auto/cursor-default`，不生成上游不存在的模型。`/v1/models`、模型管理／详情／批量选择、账户模型统计及响应 `model` 字段使用专属名；向上游仍发送原始 ID，旧 `auto/default` 请求继续兼容。回调、禁用设置、既有模型绑定及历史日志的原始 ID 不迁移；新别名在所属供应商渠道内解析，不套全局模型映射。积分倍率不换算剩余 M。

认证失效后的重新授权入口、自动签到开关位置等，下一步在相同交互风格下展开；本轮不把未对齐的旧版按钮树直接搬回。现有权限、删除确认及外部副作用保护不因版式收敛而取消。

### 积分空状态与查询反馈

- 上游成功响应中的 `TotalCount: 0, Accounts: null` 是明确的空资源包结果，归为 `status=empty, complete=true`；缺失 Accounts、非零计数配 null、错误结构仍按异常处理。
- 列表／详情／活动页显示“当前未查到有效资源包”。不把它编成余额 0，不画百分比、不据此自动禁用或解禁账户，也不回填旧资源包余额。真实失败时仍保留已有成功值并标注旧快照。
- “查询活动/余额”和详情“刷新额度”均即时答复“查询中…”，原消息先显示查询进度；上游查询在后台执行，不阻塞 TG 后续操作。结束后保留结果、北京时间及区域对应的只查询说明；若用户已切换该消息的页面，不再用旧查询结果覆盖新页。即使余额不变，再点也有进度反馈。
- 活动页直接显示积分摘要、数据更新时间及已获取的计费类型；部分失败显示具体组件和安全的错误类型／HTTP／业务码。查询异常不会再被随后重绘的普通页面覆盖，原始异常或上游敏感正文不回显。
- 中国区查询说明为“本次仅查询，未执行签到”；国际区为“本次仅查询，未申请试用额度”，不暗示查询会领取奖励。通用按钮与执行确认顺序保持原样。

## 五、实施范围与验收约束

以完整技术方案的协议与生命周期设计为技术依据，以本稿为优先的 TG 视觉／信息层级基准。继续实现登录、导入、模型、积分和签到等完整流程；这些子页面沿用现有页面、按钮、输入与结果交互，不另建 WorkBuddy 仪表盘或设置总页。

- 本次授权为开发代码实现与隔离测试；不授权修改生产、重启、提交／发布、执行真实账号登录／刷新／签到／领取。开发 `PARROT_NO_REFRESH=1` 保持。
